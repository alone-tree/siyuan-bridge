# 列表块编辑方案

> 日期：2026-11-13
> 状态：设计已定，待实施
> 适用版本：思源 3.8.10，思源桥 1.14.0 之后

## 背景

当前 `siyuan_read` 把一个列表当作一个展示块，列表项和子项都不出现。`siyuan_edit` 只能按展示块定位，所以改列表里一行文字，必须整块重写。

实测 `D:\Github\siyuan-agent-bridge` 库中的文档「测试思源桥专用/列表项」（`20261113131833-9vr573h`），8 行列表内容在块树里有 22 个块：1 个列表块、8 个列表项块、8 个首段落块、3 个子列表块、1 个段落块和文档块。

思源的块引用只认列表块（`20261113131838-73w8diw`）和列表项块（`20261113131839-jzqclgn`）。列表项的第一个子块（首段落）省略块标，用户看不到也选不中。所以列表项是一等块，首段落不是。

本方案把展示单位定为列表项，不暴露首段落。

## 一、块头格式调整

所有块的块头由 `[序号] id=... type=...` 改为方括号包住全部字段：

```text
[6 id=20261113132155-es0may2 type=list]
```

内容仍另起一行，换行结构不变。

```text
[1 id=20261113131904-9xocnvs type=paragraph]
无序列表
```

代码位置：`source_code/mcp_server.py` 的 `block_metadata_line()`。所有块类型共用，包括代码块的 `language=` 和数据库的 `readonly=true`。

配套同步：`ARCHITECTURE.md` 阅读模型、嵌入块与表格相关文档中的示例、`tests/` 中的断言、插件块序号说明。

## 二、read 展示

普通阅读不变，仍输出原始 Markdown，不显示块头。

引用阅读（`include_block_ids=true`）展开列表：

```text
[10 id=20261113131838-73w8diw type=list]
  [11 id=20261113131839-jzqclgn type=list_item]
  层级1，项1
  [12 id=20261113131845-e8nkccu type=list_item]
  层级1，项2
    [13 id=20261113131856-m9wsxkg type=list_item]
    层级2，项2.1
    [14 id=20261113131918-e48gosz type=list_item]
    层级2，项2.2
      [15 id=20261113131944-lql7knr type=list_item]
      层级3，项2.2.1
  [16 id=20261113131922-2r5hq5j type=list_item]
  层级1，项3
    [17 id=20261113131928-z6ne45s type=list_item]
    层级2，项3.1
  [18 id=20261113131934-a5umu00 type=list_item]
  层级1，项4
```

规则：

- 列表块占一个序号，每个列表项各占一个序号，序号全局线性递增。
- 缩进按真实父子层级，不按序号推算。块头行和它的内容行同缩进。
- 首段落块、子列表块不单独展示，也不占序号。
- 列表项编号对应列表项块 ID，用于删除、插入和整项替换。
- 类型名用 `list` 和 `list_item`，与 `semantic_block_type()` 现有命名一致。

## 三、块单位

| 动作 | 选中的块 | 实际作用的块 | 子项 |
|---|---|---|---|
| 改文字 | 列表项 | 列表项内的首段落 | 保留 |
| 改文字并加子项 | 列表项 | 首段落加新子项 | 保留 |
| 删整项 | 列表项 | 列表项本身 | 删除 |
| 整棵替换 | 列表项到最后一个子项 | 列表项本身 | 按提交重建 |
| 项前插入 | 列表项 | 插入到同一父列表 | 不影响 |
| 项后插入 | 列表项 | 插入到同一父列表 | 不影响 |
| 整表替换 | 列表块 | 列表块本身 | 全部按提交重建 |

改文字落到首段落，是因为首段落不可引用、没有独立入口。这是块内定位，不是改写内容：提交什么就写入什么，返回什么就原样返回。

## 四、提交内容处理

选中单个列表项时，按提交内容解析出的列表结构决定作用范围。

### 4.1 只提交一个列表项，不带子列表

提交：

```markdown
- 层级1，项2改
```

结果：只替换首段落文字，原子项全部保留。

```text
[12] 层级1，项2改
  [13] 层级2，项2.1
  [14] 层级2，项2.2
```

### 4.2 提交一个列表项，带续行

```markdown
- 层级1，项2改
  第二行
```

续行没有 `- ` 前缀、缩进对齐，按 Markdown 标准属于同一项内的换行。结果只替换文字部分，原子项保留。

### 4.3 提交一个列表项，带子列表

```markdown
- 层级1，项2改
  - 层级1，项2.1加
```

结果：新子项插在最前，原子项接在后面。

```text
[12] 层级1，项2改
  [13] 层级1，项2.1加
  [14] 层级2，项2.1
  [15] 层级2，项2.2
```

### 4.4 选中范围到最后一个子项

选中 `[12]` 到 `[14]`，提交任意列表结构。

结果：整棵替换，范围内的列表项及其子项全部按提交内容重建。

```markdown
- 层级1，项2改
- 层级1，项2加
```

```text
[12] 层级1，项2改
[13] 层级1，项2加
```

原来项2.1、项2.2 消失。

### 4.5 提交多个同级项，但只选中一个列表项

拒绝。

理由：两个同级项只能有一个继承原子项，任何分配都是桥替 AI 猜意图。

错误提示：

```text
选中单个列表项时提交了多个同级项，无法确定原有子项归属。

请改用其中一种：
1. 只提交一个列表项，原有子项会保留，例如 `- 层级1，项2改`
2. 把范围选到最后一个子项，整棵替换
3. 分两次调用：先改文字，再在目标项后面插入新项
```

## 五、边界与副作用

编号顺延：插入或删除后，后面所有列表项序号都会变。AI 必须重新 read 才能继续编辑，不能沿用旧序号。

空容器：删掉列表最后一项后，思源会留下空列表块，不自动清理。删掉列表项内唯一段落时，内核会补一个空段落。两者都需要在 read 时如实展示，桥不主动清理父容器。

同级范围：范围必须对齐树结构，从某个列表项开始，到它后面某个同级条目的最后一个后代结束。跨父容器的范围（例如从子项开始、到父项的兄弟结束）拒绝。

- 移动列表项到其他父级、层级上提与下降。
- 列表类型转换（有序、无序、任务）与列表项转普通段落。
- 列表项内部多段文字时，后续段落是否单独编号。
