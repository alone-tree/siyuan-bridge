# 列表块编辑方案

> 日期：2026-11-13
> 状态：设计已定，待实施
> 适用版本：思源 3.8.10，思源桥 1.14.0 之后
> 验证样本：`/测试思源桥专用/列表项`，文档 ID `20261113131833-9vr573h`

## 1 背景

当前 `siyuan_read` 把一个列表当作一个展示块，列表项和子项都不出现。`siyuan_edit` 只能按展示块定位，所以改列表里一行文字，必须整块重写。

实测该样本文档，8 行列表内容在块树里有 22 个块：

- 1 个文档块
- 1 个段落块（列表前的说明文字）
- 1 个列表块 `20261113131838-73w8diw`
- 8 个列表项块
- 8 个首段落块
- 3 个子列表块

思源的块引用只认列表块和列表项块。列表项的第一个子块（首段落）省略块标，用户看不到、也选不中、也无法被引用。所以列表项是一等块，首段落不是。

本方案把展示单位定为列表项，不暴露首段落。

## 2 块头格式

所有展示块统一使用方括号包住全部字段，内容另起一行：

```text
[序号 id=块ID type=类型]
正文
```

规则：

- 序号为全局线性整数，从 1 开始，跨块类型连续递增。
- 类型名使用 `semantic_block_type()` 的现有命名：`paragraph`、`heading`、`list`、`list_item`、`table`、`code`、`blockquote`、`superblock`、`database`、`query_embed`、`attachment` 等。
- 代码块追加 `language=xxx`，数据库追加 `readonly=true`，表格追加 `rows=N columns=M`。
- 块头和正文之间固定一个换行，不合并成一行。
- 表格是唯一例外：块头后接空行、坐标视图提示行、空行、表格，沿用现有输出，本方案不改。

代码位置：`source_code/mcp_server.py` 的 `block_metadata_line()`，表格的行列数通过 `extra` 参数传入。

## 3 read 展示

### 3.1 普通阅读

行为不变。输出原始 Markdown，不显示任何块头：

```markdown
- 层级1，项1
- 层级1，项2
  - 层级2，项2.1
  - 层级2，项2.2
    - 层级3，项2.2.1
- 层级1，项3
  - 层级2，项3.1
- 层级1，项4
```

### 3.2 引用阅读

这是本文档的主示例，取自样本文档用当前源码实际读取的结果改造。原文第 2 个展示块是列表块，新模型下展开为 1 个列表块加 8 个列表项，后续块序号整体后移。

```text
[1 id=20261113131904-9xocnvs type=paragraph]
无序列表

[2 id=20261113131838-73w8diw type=list]
  [3 id=20261113131839-jzqclgn type=list_item]
  层级1，项1
  [4 id=20261113131845-e8nkccu type=list_item]
  层级1，项2
    [5 id=20261113131856-m9wsxkg type=list_item]
    层级2，项2.1
    [6 id=20261113131918-e48gosz type=list_item]
    层级2，项2.2
      [7 id=20261113131944-lql7knr type=list_item]
      层级3，项2.2.1
  [8 id=20261113131922-2r5hq5j type=list_item]
  层级1，项3
    [9 id=20261113131928-z6ne45s type=list_item]
    层级2，项3.1
  [10 id=20261113131934-a5umu00 type=list_item]
  层级1，项4
```

### 3.3 展示规则

- 列表块占一个序号，每个列表项各占一个序号。
- 缩进按展示层级计算，每深一层加 2 个空格。不展示的子列表块不计一级。
- 块头行和它的正文行使用相同缩进。
- 首段落块、子列表块不单独展示，不占序号。
- 列表项正文取首段落块的文字，去掉列表标记，规则见 3.5 和 3.6。
- 列表项内部有多段文字时，后续段落接在正文行后面，同样缩进，不单独编号。
- 空列表块（没有任何列表项）仍然占一个序号，正文为空行。

列表项含多段的展示：

```text
[4 id=20261113131845-e8nkccu type=list_item]
层级1，项2
这是项2的第二段
```

### 3.4 空列表块

真空列表块单独占一个序号，正文为空：

```text
[2 id=20261113131838-73w8diw type=list]
```

这条推翻了现有 `build_display_blocks()` 里“列表块 markdown 为空就下沉到子块”的分支。新模型下列表块一律占位，是否为空只看它有没有列表项。

### 3.5 任务列表

任务列表的勾选标记属于内容，保留在正文里：

```text
[4 id=20261113131845-e8nkccu type=list_item subtype=t]
[ ] 买牛奶
```

规则：

- 正文保留 `[ ]` 或 `[x]`，去掉 `- `。
- 修改勾选状态时，提交 `- [x] 买牛奶`，桥按 5.2 只改首段落文字。
- `subtype=t` 用来标识任务列表，不改现有 `semantic_block_type()` 的 `type=list`。

### 3.6 有序列表

- 正文不含 `1.` `2.` 这类序号，序号由思源按渲染位置自动生成。
- 列表块的 `type` 统一是 `list`，有序和无序的区分靠 `subtype`，read 时不额外标注。
- 插入或删除列表项后，思源自动重排编号，read 展示的是重排后的实际顺序。

### 3.7 插件与共享用例

插件页面角标必须使用同一套编号。`siyuan-plugin/block-index.js` 和 `index.js` 内联的 `collectDisplayBlockIndexes()` 同步改成展开列表项，`displayBlockNeedsChildren()` 对 `i` 返回 true。

`tests/fixtures/display_block_index_cases.json` 现有三个列表用例的期望值全部改变，必须逐条更新：

| 用例 | 现状 | 新期望 |
|---|---|---|
| `nonempty-list-container` | 只期望 1 个块 `list1` | `list1`、`item1`、`item2` 三个块，序号 1、2、3 |
| `nested-nonempty-list` | 只期望 1 个块 `outer` | `outer`、`item`、`child-item` 三个块，序号 1、2、3；`inner` 是子列表块，不占序号 |
| `empty-list-sinks-to-items` | 期望 `item1`、`item2` 两个块 | `list1`、`item1`、`item2` 三个块，序号 1、2、3 |

fixture 的条目结构只有 `index`、`id`、`type`，无法表达缩进和正文。需要增加 `indent` 和 `text` 两个可选字段，Python 和插件都按它校验；不含这两个字段的旧用例保持原样，只校验前三项。

## 4 块单位

| 动作 | 选中的块 | 实际写入位置 | 子项 |
|---|---|---|---|
| 改文字 | 列表项 | 列表项内的首段落 | 保留 |
| 改文字并加子项 | 列表项 | 首段落 + 新子项 | 保留 |
| 删整项 | 列表项 | 列表项本身 | 一起删除 |
| 整棵替换 | 列表项到最后一个子项 | 列表项本身 | 按提交重建 |
| 项前插入 | 列表项 | 同一父列表，目标项之前 | 不影响 |
| 项后插入 | 列表项 | 同一父列表，目标项之后 | 不影响 |
| 整表替换 | 列表块 | 列表块本身 | 全部按提交重建 |

改文字落到首段落，是因为首段落不可引用、没有独立入口。这是块内定位，不是改写内容：提交什么就写入什么，返回什么就原样返回。

## 5 提交内容处理

### 5.0 读写格式差异

read 的列表项正文不带 `- ` 标记，因为序号和缩进已经表达了列表结构；edit 提交时必须带 `- ` 或 `1. `，因为思源按 Markdown 解析插入内容。

这个差异是有意的，工具描述和 Skill 里都要写明，避免 AI 因为 read 里没有 `-` 就提交不带列表标记的纯文本。

### 5.1 判定流程

先按动作分流：

1. `action=default_block_replace`：一律整棵替换，不保留任何子项，见 5.5 和 5.9。
2. `action=delete`：删除选中列表项及其全部后代，见 5.6、5.7。
3. `action=insert_before` / `insert_after`：在目标列表项前后插入，见 5.8。
4. `action=append` / `insert_assets` / `table_edit`：不适用于列表项，见 5.10。
5. `action=single_block_replace`：进入下面的细则。

`single_block_replace` 的细则：

1. 如果 `markdown` 和 `markdown_file` 都没传，报 `validation:missing_param`。
2. 解析 `markdown`。解析失败，或解析后没有任何列表项，报 `validation:wrong_shape`。
3. 选中的是列表块（`type=list`）：按 5.9 整表替换。
4. 同时传了 `end_index` 和 `end_id`：按 5.5 整棵替换。
5. 只传了 `end_index` 或只传了 `end_id`：报 `validation:missing_edit_range`。
6. 解析出多个顶层列表项：报 `validation:wrong_shape`，提示原文见 5.10。
7. 解析出 1 个列表项且没有子列表，正文只有一行：按 5.2 只改文字。
8. 解析出 1 个列表项且没有子列表，正文有多行：按 5.3 改文字并加段落。
9. 解析出 1 个列表项且带子列表：按 5.4 加入子项并保留原子项。

`default_block_replace` 是 enum 第一项，AI 最容易默认选它。`action` 参数描述里必须写明：要保留子项只能用 `single_block_replace`。

实现提示：现有 `single_block_replace` 用 `markdown_has_multiple_blocks()` 判断是否会生成多块，该函数只按空行判断，带嵌套列表的提交不会触发拒绝。列表的判定要在它之前完成，否则 5.4 的提交会被旧逻辑拦掉。

### 5.2 改一行文字

原来：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2
    [5 id=itemB1 type=list_item]
    层级2，项2.1
```

选中：`start_index=4`，`start_id=itemB`，`action=single_block_replace`，不传 `end_index` / `end_id`。

提交：

```markdown
- 层级1，项2改
```

结果：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2改
    [5 id=itemB1 type=list_item]
    层级2，项2.1
```

列表项块 ID `itemB` 不变，首段落文字被替换，子列表和子项 `itemB1` 完全不动。

### 5.3 项内多段

原来：

```text
[4 id=itemB type=list_item]
层级1，项2
  [5 id=itemB1 type=list_item]
  层级2，项2.1
```

选中：`start_index=4`，`start_id=itemB`，`action=single_block_replace`。

提交：

```markdown
- 层级1，项2改
  补充说明
```

结果：

```text
[4 id=itemB type=list_item]
层级1，项2改
补充说明
  [5 id=itemB1 type=list_item]
  层级2，项2.1
```

续行没有 `- ` 前缀、缩进对齐首行内容，按 Markdown 标准属于同一列表项内的换行。首段落更新为第一行文字，其余行作为该项的后续段落插入，子项保留。

如果该项原来已有多段，提交内容整体替换原有全部文字段落，子列表保留。

### 5.4 提交一个列表项，带子列表

原来：

```text
[4 id=itemB type=list_item]
层级1，项2
  [5 id=itemB1 type=list_item]
  层级2，项2.1
  [6 id=itemB2 type=list_item]
  层级2，项2.2
```

选中：`start_index=4`，`start_id=itemB`，`action=single_block_replace`。

提交：

```markdown
- 层级1，项2改
  - 层级2，项2.0加
```

结果：

```text
[4 id=itemB type=list_item]
层级1，项2改
  [5 id=itemB0 type=list_item]
  层级2，项2.0加
  [6 id=itemB1 type=list_item]
  层级2，项2.1
  [7 id=itemB2 type=list_item]
  层级2，项2.2
```

规则：

- 首段落替换为新文字。
- 提交的子项插入到原有子项之前，顺序与提交内容一致。
- 原有子项按原顺序接在后面，全部保留。
- 新子项使用新块 ID，旧子项 ID 不变。

如果选中的列表项原本没有子项，结果就是新子项直接成为它的子列表，没有旧子项可接。这是 5.4 的特例，不需要另走 5.5。

### 5.5 整棵替换

原来：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2
    [5 id=itemB1 type=list_item]
    层级2，项2.1
    [6 id=itemB2 type=list_item]
    层级2，项2.2
  [7 id=itemC type=list_item]
  层级1，项3
```

选中：`start_index=4`，`start_id=itemB`，`end_index=6`，`end_id=itemB2`，`action=single_block_replace` 或 `default_block_replace`。

提交：

```markdown
- 层级1，项2改
- 层级1，项2加
```

结果：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2改
  [5 id=itemD type=list_item]
  层级1，项2加
  [6 id=itemC type=list_item]
  层级1，项3
```

规则：

- 范围内所有列表项及其子项全部删除，按提交内容重建。
- 提交内容的第一项占据 `start_id` 的位置，后续项依次成为兄弟。
- 原范围内未在提交中出现的子项全部消失。
- 范围外的兄弟项（`itemA`、`itemC`）不受影响，块 ID 不变。

合法的范围必须满足：`end_id` 是 `start_id` 同级某个列表项的最后后代，或者就是那个同级列表项本身。

合法示例：

```text
[4] 到 [4]    单个列表项
[4] 到 [6]    列表项 B 及其子项
[4] 到 [7]    列表项 B、C 两个完整子树
```

非法示例：

```text
[5] 到 [7]    起点是 B 的子项，终点是 B 的兄弟 C
```

非法范围拒绝，报 `validation:operation_order`，提示重新选择或改用整表替换。

### 5.6 删除一项

原来：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2
    [5 id=itemB1 type=list_item]
    层级2，项2.1
```

选中：`start_index=4`，`start_id=itemB`，`action=delete`。

提交：无。`action=delete` 不接收 `markdown` 和 `markdown_file`，传了直接忽略，不报错。

结果：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
```

`itemB` 及其子项 `itemB1` 一起删除。后续列表项序号依次前移。

### 5.7 删除范围

原来：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2
    [5 id=itemB1 type=list_item]
    层级2，项2.1
  [6 id=itemC type=list_item]
  层级1，项3
```

选中：`start_index=4`，`start_id=itemB`，`end_index=5`，`end_id=itemB1`，`action=delete`。

提交：无。

结果：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemC type=list_item]
  层级1，项3
```

范围删除的合法性与 5.5 相同，跨父容器拒绝，报 `validation:operation_order`。

删除列表块本身（选中 `[2]`）时，整个列表删除，不留空容器。

删除后列表变空时，思源留下空列表块，桥不主动清理，read 时按 3.4 展示。

### 5.8 插入

原来：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2
    [5 id=itemB1 type=list_item]
    层级2，项2.1
```

#### 5.8.1 项前插入

选中：`start_index=4`，`start_id=itemB`，`action=insert_before`。

提交：

```markdown
- 层级1，项1.5
```

结果：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemX type=list_item]
  层级1，项1.5
  [5 id=itemB type=list_item]
  层级1，项2
    [6 id=itemB1 type=list_item]
    层级2，项2.1
```

#### 5.8.2 项后插入

选中：`start_index=4`，`start_id=itemB`，`action=insert_after`。

提交：

```markdown
- 层级1，项2.5
  - 层级2，项2.5.1
```

结果：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2
    [5 id=itemB1 type=list_item]
    层级2，项2.1
  [6 id=itemY type=list_item]
  层级1，项2.5
    [7 id=itemY1 type=list_item]
    层级2，项2.5.1
```

规则：

- 插入的列表项与目标同级，父列表不变。
- 项后插入时，新项排在目标项的整棵子树之后，不是插进它的子列表。
- 锚点是列表块而不是列表项时，`insert_before` 插到列表块之前成为兄弟块，`insert_after` 插到列表块之后；提交内容必须解析为列表项，否则报 `validation:wrong_shape`。

给一个已有子项的列表项追加子项：选中它最后一个子项，用 `insert_after`，提交与那个子项同级的列表项。

给一个没有子项的列表项添加第一个子项：用 `single_block_replace`，提交带子列表的内容，见 5.4 的特例。

### 5.9 整表替换

原来：

```text
[2 id=list1 type=list]
  [3 id=itemA type=list_item]
  层级1，项1
  [4 id=itemB type=list_item]
  层级1，项2
```

选中：`start_index=2`，`start_id=list1`，`action=default_block_replace`。

提交：

```markdown
1. 甲
2. 乙
   - 乙的子项
3. 丙
```

结果：

```text
[2 id=itemP type=list]
  [3 id=itemQ type=list_item]
  甲
  [4 id=itemR type=list_item]
  乙
    [5 id=itemR1 type=list_item]
    乙的子项
  [6 id=itemS type=list_item]
  丙
```

规则：

- 整表替换必须用 `default_block_replace`，会删除列表块并重建。
- 原列表块和全部子块的 ID 都失效。
- 因为走 `default_block_replace`，现有的 `reference_policy` 反链保护自动生效，与其它整块替换一致。
- 列表类型（有序、无序、任务）由提交内容决定。
- 用 `single_block_replace` 选列表块也会按整表替换处理，但它会保留列表块 ID 而让所有子块 ID 失效，反链检查覆盖不到子块，因此工具侧要拒绝：选列表块做替换时如果 `action=single_block_replace`，报 `validation:wrong_shape`，提示改用 `default_block_replace`。

### 5.10 拒绝场景

| 情况 | 错误码 | 提示要点 |
|---|---|---|
| `markdown` 和 `markdown_file` 都没传 | `validation:missing_param` | 要求提供 markdown 或 markdown_file |
| 解析失败或解析后没有列表项 | `validation:wrong_shape` | 要求提交合法 Markdown 列表 |
| 解析出多个同级项但只选了一个列表项 | `validation:wrong_shape` | 说明无法确定原子项归属，给出三条替代路径 |
| 只传 `end_index` 或只传 `end_id` | `validation:missing_edit_range` | 要求两个都传 |
| 范围跨父容器 | `validation:operation_order` | 说明范围必须覆盖完整子树 |
| `start_id` 与当前 `start_index` 不匹配 | `conflict:stale_block_id` | 要求重新引用阅读 |
| 选列表块用 `single_block_replace` | `validation:wrong_shape` | 要求改用 `default_block_replace` |
| 对列表项用 `append`、`table_edit`、`insert_assets` | `validation:wrong_target_type` | 说明该动作不适用于列表项 |

以上错误码全部复用 `source_code/mcp_server.py` 现有常量，不新增。

下面两个示例可用于复核：

多同级项，选中单个列表项：

```text
选中：start_index=4，start_id=itemB，action=single_block_replace
提交：
- 层级1，项2改
- 层级1，项2加
结果：拒绝，validation:wrong_shape
提示：
选中单个列表项时提交了多个同级项，无法确定原有子项归属。

请改用其中一种：
1. 只提交一个列表项，原有子项会保留，例如 `- 层级1，项2改`
2. 把范围选到最后一个子项，整棵替换
3. 分两次调用：先改文字，再在目标项后面插入新项
```

跨父容器范围：

```text
原来：[3] itemA / [4] itemB → [5] itemB1 / [6] itemC
选中：start_index=5，start_id=itemB1，end_index=6，end_id=itemC
结果：拒绝，validation:operation_order
提示：
范围起点是第 5 块的子项，终点是它的兄弟第 6 块，无法确定插入层级。
请把范围选到完整的兄弟子树，例如 4 到 6，或改用整表替换。
```

## 6 边界与副作用

编号顺延：插入或删除后，后面所有列表项序号都会变。AI 必须重新 read，不能沿用旧序号继续编辑。

空容器：删掉列表最后一项后，思源留下空列表块，桥不清理，按 3.4 展示。删掉列表项内唯一段落时，内核补一个空段落，read 时该列表项正文为空行。

线性编号：列表项按文档顺序深度优先编号。范围必须对齐树结构，从某个列表项开始，到它后面某个同级条目的最后一个后代结束。

列表项 ID 保留：改文字、加子项时，被选中列表项的 ID 不变。整棵替换、删除、整表替换时相关 ID 失效，走现有反链保护。

回环：列表项内部允许继续嵌套列表，深度没有额外限制，按真实块树递归。

图文混排：列表项内部的图片按现有附件规则处理，不新增图片编辑能力。

## 7 待定

以下问题本轮未定，实施前需要单独确认：

- 引用块（引述块）是否采用同一套展开规则，其内部段落、列表、表格如何编号。
- 跨父容器的多项替换。
- 移动列表项到其他父级、层级上提与下降。
- 列表类型转换、列表项转普通段落、普通段落转列表。
- 列表项内部有多段时，后续段落是否需要在某些场景单独可定位。
- 列表项内部含表格、代码块时的定位与编辑，本轮只确认了这些块可以存在于列表项内部，没有定编辑规则。
