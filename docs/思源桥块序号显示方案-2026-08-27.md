# 思源桥块序号显示方案

> 状态：已实施（v1.8.0 工作区，尚未发布）。
> 日期：2026-08-27；实施：2026-08-28。

## 一、需求与目标

思源桥的 `siyuan_read(include_block_ids=true)` 会给文档中的展示块生成 `[1]、[2]、[3]…` 序号。AI 经常用“第 25 块”与用户交流，但思源页面当前没有显示这套序号，用户无法直接定位。

目标是在思源插件中显示与 AI 使用read工具读取结果一致的块序号：

- 用户在思源正文中直接看到 `1、2、3…`，不需要识别块 ID。
- 插件显示的是当前文档的实时序号。
- AI 每次使用序号与用户交流前，重新读取当前文档。
- 序号只作为界面覆盖层，不写入笔记正文或块属性。

## 二、已确认决策

### 2.1 编号语义

采用“始终显示当前实时编号”，不采用“显示 AI 最近一次读取快照”。

因此：

- 文档插入、删除或移动块后，插件自动重新编号。
- AI 或用户修改文档后，旧序号立即失效；AI 再次引用序号前必须重新读取。
- 如果 AI 已经说完“第 25 块”，随后文档结构又发生变化，旧对话中的“第 25 块”无法继续保持原含义。这是实时编号的必然限制，可以接受。

### 2.2 唯一顺序来源

编号顺序必须来自思源 `/api/block/getChildBlocks` 返回的完整块树，AI和人类看到的应该是同一个序号，同一个来源。不要另外使用其他来源，不能使用：

- 页面 DOM 中第几个元素；
- 思源前端的 `data-node-index`；
- SQL 的 `parent_id + sort`；
- CSS 计数器。

项目已经验证，部分导入文档的同级块 `sort` 可能全部相同，只有 `getChildBlocks` 能可靠还原思源顺序。长文档还存在动态加载，未滚动到的块可能不在 DOM 中，因此 DOM 只能用于把已计算出的序号贴到对应块旁，不能用于计算序号。

## 三、当前编号算法

当前权威实现为 `source_code/mcp_server.py` 的 `build_display_blocks()`。插件必须产生与 `include_block_ids=true` 相同的 `index → block ID` 结果。

规则如下：

1. 从文档根块开始，通过 `getChildBlocks` 做深度优先遍历。
2. 使用块 ID 去重；每个块只处理一次。
3. 文档根块 `d` 不编号。
4. 数据库 `av` 占一个编号。
5. 非超级块且 Markdown 为空的块不编号；若它是可遍历容器，则继续遍历子块。
6. 非空列表容器 `l` 整体占一个编号，其列表项和子孙不再重复编号。
7. 空列表容器不占号，继续下沉到其列表项。
8. 列表项 `i`、列表 `l`、表格 `t` 的 Markdown 已包含子树内容，编号后不继续遍历子孙。
9. 表格 `t` 整体占一个编号。
10. 超级块 `s` 在引用阅读模式下自身占一个编号，内部块继续编号。
11. 标题 `h` 自身占一个编号，标题下内容继续编号。
12. 最终编号按加入展示块列表的顺序，从 1 连续递增。

当前相关源码：

- `source_code/client.py:235-239`：`get_child_blocks()`。
- `source_code/mcp_server.py:207-213`：块类型规则常量。
- `source_code/mcp_server.py:939-948`：`[index] id=... type=...` 元数据格式。
- `source_code/mcp_server.py:1430-1562`：`build_display_blocks()`。
- `source_code/mcp_server.py:2763-2873`：`siyuan_read` 块窗口。

## 四、插件设计

### 4.1 用户入口

增加两个等价入口：

- 思源桥设置页开关：“显示思源桥块序号”。
- 命令面板命令：“显示/隐藏思源桥块序号”。

默认开启。开关状态使用插件自身配置保存，不写入笔记。插件启用且序号开启时提示用户：左侧数字来自思源桥。

### 4.2 页面显示

- 在每个参与编号的块左侧显示弱化数字角标，如 `25`。
- 数字角标不进入 `contenteditable`，不参与复制、导出、撤销和块事务。
- 角标通过块 ID 与 `.protyle-wysiwyg [data-node-id]` 对应。
- 确保AI使用read工具看到的块序号、块ID对应与人类在页面看到的一致
- 关闭开关、关闭文档、禁用插件或卸载插件时必须清理全部角标和监听器。

### 4.3 实时重算

监听当前版本思源插件 API 中与编辑器生命周期和块事务对应的事件，实施前以官方类型定义再次核对具体事件名。当前候选包括：

- `loaded-protyle-static`；
- `loaded-protyle-dynamic`；
- `switch-protyle`；
- `ws-main` 中的块事务；
- `destroy-protyle`。

处理原则：

1. 打开或切换文档时计算完整 `ID → 序号` 映射。
2. 只有新增、删除、移动块才计算（这些事情会导致块序号变化）。在块内打字、修改样式不应该重算（这些动作不会改变块序号和ID），避免输入每个字符都遍历完整块树
3. 动态加载新 DOM 块时不重新决定编号，只把已有映射中的序号补到新出现的块上。
4. 读取或计算失败时删除该文档现有角标，并显示“块序号暂不可用”；禁止保留可能错误的旧编号。
5. 多窗口、分屏中的每个 Protyle 实例独立维护显示状态；同一文档使用同一实时块树结果。

## 五、一致性保障

实时方案要求 Python MCP 和 JavaScript 插件分别执行同一规则，尽将代码封装，只维护一份，不要两边维护，哪里需要就复用。避免以后只修改其中一端，导致静默漂移。

- 修改展示块规则时，必须同时修改共享样例、Python、插件和相关文档。

共享样例至少覆盖：

- 标题、段落、代码块；
- 普通空块；
- 非空列表容器；
- 空列表容器及列表项；
- 多级列表；
- 超级块；
- 表格；
- 数据库；
- 重复块 ID 去重。

当前测试缺口：`include_block_ids=true` 时超级块自身占号尚无独立断言，需要补充。

## 六、AI 使用规则

同步修改思源桥 Skill：

1. AI 面向用户提到“第 N 块”前，必须调用 `siyuan_read(include_block_ids=true)` 读取当前版本。
2. AI 或用户修改文档后，不得继续沿用修改前的序号。
3. 再次引用序号前重新读取。
4. 面向用户使用“第 25 块”即可；块 ID 继续作为 MCP 编辑安全校验，不要求用户识别或查找。

## 九、验收标准

| 场景 | 期望 |
|---|---|
| 普通标题、段落、代码块 | AI 返回的每个 `[N] id=...` 与页面同 ID 块旁的 `N` 完全一致 |
| 多级列表 | 非空列表整体一号；空列表按现有规则下沉；不重复编号 |
| 超级块 | 超级块自身和内部块的序号均与引用阅读一致 |
| 表格 | 整张表只占一个编号；AI 的行列坐标编辑不受影响 |
| 数据库 | 数据库块只占一个编号，不把数据库内部行列当正文块编号 |
| 500 块以上长文档 | 未滚动到底时编号计算仍覆盖全文；滚动加载后新出现块得到正确角标 |
| 手工插入、删除、移动块 | 防抖后自动重排，页面无残留旧编号 |
| AI 编辑成功 | 插件自动反映最新实时编号；AI 再引用前重新读取 |
| 双窗口和分屏 | 各文档互不串号，同一文档显示一致 |
| 关闭功能或卸载插件 | 角标和监听器清理，笔记正文与块属性没有变化 |
| API 或计算失败 | 不显示可能错误的旧序号，明确提示暂不可用 |

## 十、依据与不确定性

### 已核实依据

- 思源支持块级结构和 `/api/block/getChildBlocks`：<https://github.com/siyuan-note/siyuan/blob/master/API_zh_CN.md>
- 官方插件样例提供 `loaded-protyle-*`、`switch-protyle`、`destroy-protyle` 等事件示例：<https://github.com/siyuan-note/plugin-sample/blob/main/src/index.ts>
- 社区已有显示顶层块序号的插件能力，证明纯界面显示可行，但其编号语义不等于思源桥：<https://github.com/Zuoqiu-Yingyi/siyuan-plugin-custom-block/blob/main/public/README.md>

### 实施前仍需核对

- 当前安装的思源版本对应插件 API 类型定义和各事件 payload。
- 最适合当前 DOM 结构的角标挂载位置，确保不进入编辑内容、不影响表格、列表和超级块布局。
- 大文档频繁编辑时完整遍历的实际耗时，据实决定防抖时间；不得预先增加复杂缓存。
