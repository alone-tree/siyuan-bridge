# Markdown 文件引用附件导入方案

> 状态：已按本文契约实现。后续修改仍必须先重新核对思源当前源码/API。

## 1. 需求背景

`markdown_file` 已支持把本地 Markdown 正文导入 `siyuan_create` 和 `siyuan_edit`，但当前只导入文本。Markdown 中引用的本地图片或附件仍保留原路径，进入思源后通常无法正常使用；网络图片和网络附件地址则可以由思源直接显示或访问，无需处理。

目标是在不新增工具和参数的前提下，让 `siyuan_create(markdown_file=...)` 与 `siyuan_edit(markdown_file=...)` 使用同一套附件后处理流程，把可访问的本地引用转为思源附件，同时保持网络地址不变。

## 2. 已有能力

项目已经具备实现所需的基础能力：

- `markdown_file`：读取本地 Markdown，并通过 create/edit 的现有写入流程导入正文。
- 文档和块读取：写入后可取得文档 ID、块 ID 和块 Markdown。
- `insert_local_assets()`：调用思源 `/api/asset/insertLocalAssets`，由思源负责复制、命名和去重，并返回 `assets/...` 路径。
- `resolve_uploaded_asset_paths()`：把本地路径与思源返回路径对应起来。
- `_update_block_preserving_attrs()`：原地更新块 Markdown，同时保留块 ID 和块属性。
- create/edit 现有快照、权限校验和写入验证机制。

现有 `siyuan_edit(action="insert_assets")` 会在锚点后创建新附件块，不能直接用于替换 Markdown 内已有引用；本功能只复用它已有的附件上传和返回路径解析能力。

## 3. 目标行为

- create 和 edit 导入 Markdown 文件后，自动处理本次写入内容中的本地图片与附件引用，不设置引用数量上限。
- 除 `file://` 外，任何带合法 URI scheme 的链接都保持不变，不访问调用端文件系统；`assets/...` 等思源已有资源路径也保持不变。
- 纯文内锚点（如 `[跳到安装说明](#安装说明)`）纳入写入后链接处理：URL 解码后的锚点文字与整篇目标文档的标题文字匹配，不区分标题层级和英文大小写；全文唯一匹配时，将目标替换为 `siyuan://blocks/<标题块ID>`，不生成 `((块ID))` 块引用；存在多个同名标题时保留原始链接并警告；无匹配时也保留原始链接并警告。
- `file://` 地址按本地引用处理：普通文件上传为 `assets/...`，目录使用思源返回的 `file://` 链接。
- 相对路径以 `markdown_file` 所在目录为基准解析为绝对路径；兼容 Markdown 尖括号包裹和 percent-encoding，解析文件时对路径部分解码。
- 不限制引用必须位于 Markdown 文件所在目录内；绝对路径、`../` 越级路径和目录外文件只要 MCP 进程可读，都允许处理，`confirmed=true` 视为对本次 Markdown 正文及其本地引用的整体写入授权。
- 标准 Markdown 链接指向本地目录时，也调用思源原生能力处理，并把链接目标替换为思源返回的 `file://` 链接；不递归上传目录。
- 普通链接指向本地 `.md` 文件时不猜测导航语义，仍按普通附件上传。
- 原则上把本地路径交给思源原生 API 处理。已核对思源当前源码：`insertLocalAssets` 会直接对传入字符串执行 `os.Stat` / `os.Open`，query 或 fragment 会被当成文件名的一部分并导致失败；因此本地引用含 `?…` / `#…` 时，Bridge 去掉后缀后上传实际文件，最终使用思源返回路径，不负责保留被去掉的后缀。
- Bridge 不为重复引用维护去重表或路径映射；按实际链接顺序调用思源原生能力，附件去重交给思源处理。
- 引用式链接按思源导入后的实际链接处理，不承诺保留源 Markdown 的引用定义写法，也不为共享定义增加单独的去重逻辑。
- 本地文件不存在、不可读或上传失败时，保留原引用，正文导入仍算成功，并在结果中列出未处理项。
- 本地文件超过现有 20 MB 大文件阈值时不自动上传，保留原引用并在结果中警告；正文导入仍算成功，不新增确认参数。
- 上传成功后，只替换原块中的链接目标，不改变 alt、标题、周围文字和其他链接。
- 原块通过 `_update_block_preserving_attrs()` 更新，不创建替代块，不删除原块，保持块 ID 和块属性。
- 不新增 MCP 工具、不新增参数；只有 `markdown_file` 启用此流程，直接传入 `markdown` 时不扫描调用端文件系统。

第一版处理标准 Markdown 的行内图片、行内链接、引用式链接和尖括号自动链接；只有被标准 Markdown 解析为图片或链接的目标才进入附件流程，不额外改写 Markdown 语法，代码围栏和行内代码中的文本不处理。

```markdown
![图片](./images/a.png)
[附件](../files/report.pdf)
[压缩包][archive]

[archive]: ./files/materials.zip
```

HTML 链接或图片、Wiki 嵌入等非标准 Markdown 语法不在第一版范围内。

## 4. 统一处理流程

### 4.1 正文先按现有流程写入

1. `siyuan_create` 或 `siyuan_edit` 按当前行为读取 `markdown_file`。
2. 完成权限校验、快照和正文写入。
3. 取得目标文档 ID，以及本次写入或修改产生的块 ID。

附件处理是正文写入后的后处理，不因源 Markdown 中存在失效文件而阻止正文导入。`siyuan_create` 写入成功但未能取得文档 ID 时，正文仍返回成功，全部本地引用保持原样，并明确警告因缺少文档 ID 未执行附件处理。

### 4.2 只扫描本次影响的块

- `siyuan_create` 新建或覆盖：扫描写入后的目标文档块。
- `single_block_replace`：扫描被原地替换的目标块。
- `default_block_replace`、`insert_before`、`insert_after`、`append`：扫描本次新生成的块。

不扫描 edit 未触及的历史块，避免重复处理文档中已有引用。

### 4.3 逐处处理引用

对每个受影响块：

1. 直接读取思源当前块 Markdown，识别标准图片和附件链接；不查询 spans 表，不引入 Markdown 解析库。独立代码块不扫描。
2. 纯文内锚点按整篇目标文档的唯一标题匹配，命中则替换为 `siyuan://blocks/<标题块ID>`。
3. 其他链接判断目标是否为本地路径；网络地址和思源已有资源路径直接跳过。
4. 相对路径以 Markdown 文件父目录为基准转为绝对路径。
5. 文件不存在或不可读：保留原链接，记录提示，继续处理下一处引用。
6. 文件或目录可用：针对这一处引用调用一次 `insert_local_assets(document_id, [absolute_path])`。
7. 从返回结果取得路径，将这一处原链接目标替换为思源返回值：普通文件为 `assets/...`，目录为 `file://`。
8. 一个块内所有引用处理完成后，用 `_update_block_preserving_attrs()` 原地更新该块。

同一文件出现多次时重复执行第 5 步，Bridge 不维护去重表。

### 4.4 读回验证与结果

处理完成后重新读取受影响块，确认：

- 上传成功的本地引用已替换为思源返回路径；
- 网络引用和处理失败的本地引用保持原样；
- 块 ID 未变化。

返回结果在现有正文写入结果上增加附件处理摘要，包括成功项、未找到项、上传失败项和块更新失败项。

## 5. 失败与残留边界

附件后处理采用尽力完成语义，不改变正文写入的成功结果：

- 文件不存在或上传失败：不修改该引用，只返回提示。
- 某个块更新失败：该块保留当时内容，继续报告已成功和未成功的项目，不撤销整篇正文导入。
- 上传成功但块更新失败时，思源资源可能已存在但未被正文引用。由于资源可能被思源去重复用，Bridge 不自动删除，只在结果中说明。
- create/edit 原有快照仍是用户需要整体恢复时的保险，不新增自动 checkout 或复杂事务机制。
