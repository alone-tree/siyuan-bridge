# 读文档时返回图片 — 需求文档

## 背景：我要解决什么

AI 读思源笔记时，图片只以文件路径的形式出现在文本里。AI 通常不会主动去打开这些文件看图（AI非常懒，必须要我手动提醒才会去读），结果是图片里的信息被整体丢掉——截图、图表、手写笔记这类内容等于没读。

需要：读文档时，图片和文字一起给到 AI，让它不用额外动作就能看到图。

## 需求

### 1. 一个开关

在插件设置页提供一个开关：「读文档时默认返回图片」。

- 打开：AI 读笔记时自动带上图片。
- 关闭：保持现在的行为，只返回文字和图片的文件路径。

### 2. 图片和文字一起返回，保持原有顺序

返回的内容按文档顺序混排：文字段落和它里面的图片待在一起，
而不是把所有图片堆在最后。

### 3. 读到哪里就返回到哪里，不限制张数

本次读的是文档的哪一段，就把那一段里的全部图片都返回。

- 不设「最多几张图」这类限制。
- 不因为图多就少给。

### 4. 截断只保留当前的设定

唯一允许的截断，是当前已有的令牌数或块数，也就是现有的翻页窗口机制，图片同样计入这个上限。超过上限就按现有方式翻页继续读。

不允许因为「图片太多」「图片太大」这类内部理由私自省略图片。

### 5. 真的返回不了的图，必须明说

如果某张图确实无法随文本一起返回（格式不支持、体积超出可传输范围等），
要在它本该出现的位置明确写清楚：

- 这张图没有返回；
- 原因是什么；
- 文件在哪里。

保留文件路径，不能无声跳过。

### 6. 生效方式

在设置里改完开关后，由 AI 平台决定何时重新连接思源桥；重新连接后新设置生效。改设置相当于改代码，通常需要重新加载整个MCP才会生效，思源桥本身的代码不需要为此做任何额外操作。

## 不做的事

- 不要求对图片做压缩、缩放或重新编码（暂定，但对于不支持的图片格式，后期可以考虑将其转为PNG或者JPG之类）
- 不改变读文档以外的功能（搜索、写入、编辑）的行为。
- 不引入任何「悄悄帮我少返回」的机制。

## 已定决策（2026-09-24）

1. 返回协议：MCP 多模态内容混排——content 数组按文档顺序交替放置文本块和图片块（图片为 base64 + MIME 类型），不采用 Markdown 嵌图。
2. 图片计价：每张图按固定 1,568 token 计入现有令牌预算（取 Anthropic 官方文档单图上限；实测主流厂商 1024×1024 区间 693-1,379）。块数与 token 任意一个触发即翻页，不设张数上限。
3. 单张体积上限：20 MB，与 `siyuan_edit(action=insert_assets)` 的大文件阈值一致。超限图片默认不内联，按第 5 条在原位置声明；AI 获得用户明确同意后，可用读侧确认参数强制内联（语义对应上传侧 `upload_large_files=true`）。
4. 处理范围：只处理图片。本地图（`assets/...`，走现有 get_asset 提取通道）和网络图（下载后转 base64）都处理；范围以思源前端图片扩展名清单为准（17 个后缀）。平台不支持内联的格式（SVG、AVIF、BMP、TIFF、ICO 等）按第 5 条声明。
5. 开关默认值：插件安装时默认关闭；用户打开后状态持久保存为开启。
6. 成功内联的图片，正文中的原文件路径仍然保留。
