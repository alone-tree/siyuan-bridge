# start 启动与展示优化讨论

状态：首轮实现通过验证；用户修订为复用现有统计，待调整。现行规范见 `ARCHITECTURE.md` 的「siyuan_start」「索引模型」「嵌入块读取」。

## 已确认范围

- `start` 实时加载隐私规则并刷新必要的文档元数据，跳过全库字数、块数和字符数统计；`siyuan_operate(action=refresh)` 重新统计并保存到现有 docs.jsonl。start 按文档 ID 复用现有统计，不新增缓存文件或后台任务。
- 启动包继续展示缓存中的字数和块数，明确注明不是实时统计。新文档或无统计时显示「未统计」；有未统计文档的汇总也标为未统计，避免把部分和误报成完整总数。删除或隐藏的文档从当前可见集合排除，不参与汇总。
- 用户要求和工作空间索引共用 read 的展示块和嵌入解析逻辑。启动只输出正文、嵌入来源路径和引用层级，省略嵌入 SQL、统计和编辑提醒；read 默认行为不变。
- 先解析隐私规则、刷新可见索引，再读取可见系统文档正文和可见嵌入来源；不通过整篇导出提前展开来源。保持重复文档合并、占位符和过期提醒。
- 保留完整正文和现有嵌入递归/可见匹配约束，不新增启动内容截断。内置指南全文、索引创建指南路径及用户手写的数字保留。

## 依据与验证

改动前真实开发版轻量计时：start 内部 6.994 秒，其中全库统计 6.464 秒（92.4%）。原始记录在主仓库 `start-performance-probe/20261112/`；扣除统计的差值不是升级后实测。

验证元数据刷新不执行统计查询、显式 refresh 恢复统计；嵌套嵌入、隐藏来源不读取、占位符、同名文档合并和 read 输出回归。单测后逐次调用能力库开发版核对 start/read/list/refresh 和耗时。开发版按用户要求保持保活，不部署或发布。
