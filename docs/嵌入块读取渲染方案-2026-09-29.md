# 嵌入块读取渲染方案（2026-09-29）

## 背景

- 用户在工作空间索引中使用嵌入块（`{{select ...}}`）聚合各笔记本概览（见 AI实践笔记《发现一个思源桥MCP的妙用》）。
- 实测（思源 3.8.5，bridge 1.10.1）：
  - `siyuan_start` 走 `/api/export/exportMdContent`（`refMode: 0, embedMode: 0`），内核 `resolveEmbedR` 在 embedMode 0 下**渲染嵌入内容**，start 返回中嵌入块已展开。
  - `siyuan_read` 走 `getChildBlocks` 展示块路径，嵌入块只显示 `{{...}}` 原始 SQL，不渲染。
  - 注意：思源 3.7.3（2026-08 实测）下 embedMode 0 会整体丢弃嵌入块，该旧结论已过时；此行为与思源版本相关，升级需回归。
- 问题：同一嵌入块，read 拿到的与 start / 思源 UI 不一致，AI 通过 read 看不到嵌入内容。

## 目标行为（用户已定格式，2026-09-29 第二轮）

`siyuan_read` 对嵌入块（query_embed）的返回格式，读写/只读权限一致；引用阅读模式仅多一行 `[n] id=... type=query_embed` 元数据行，内部内容同样不加序号：

```
{{嵌入块语法}}
嵌入块来源：<文档绝对路径> <文档ID>[ 块ID]
嵌入块内容：
> <嵌入内容按引用格式完整呈现，逐行加 > 前缀；嵌套嵌入整组递归进引文>
嵌入内容共X个块，当前展示N个块
嵌入内容来自其他文档，不要把嵌入块当普通块编辑（避免 SQL 被改丢引用），要改去来源文档
```

- 来源行：嵌入目标是整篇文档时只到文档ID；目标是文档内的块时追加块ID。
- 统计行与提示行任何情况下都必须存在（含 0 结果、丢失、无权限）。
- 无结果、丢失、无权限或被隐私过滤时统一按「查无此块」处理，不透露原因或隐藏目标信息：

```
{{嵌入块语法}}
嵌入块来源：查无此块
嵌入块内容：
> 查无此块
嵌入内容共0个块，当前展示0个块
嵌入内容来自其他文档，不要把嵌入块当普通块编辑（避免 SQL 被改丢引用），要改去来源文档
```

- 嵌套嵌入（层级规则，用户已定）：设嵌入块所在位置的引用层级为 L（直接读取文档中的嵌入块 L=0）——结构行（`{{...}}`、嵌入块来源、嵌入块内容）渲染在层级 L；「嵌入块内容：」之后的嵌入内容渲染在层级 L+1；嵌入内容里再出现嵌入块时，其结构行渲染在 L+1（与周围内容同级），内容再深一级，以此类推。
- 停止展开（用户已定格式）：不再输出内容引文，「嵌入块内容：」后直接跟停止原因。原因与来源行规则：
  - 循环：`嵌入块内容：循环嵌套，停止解析`，来源行照常显示真实来源；
  - 嵌入层级超过 7 层：`嵌入块内容：嵌入层级超过7层，停止解析`，来源行照常显示真实来源；
  - 整个嵌入块无法纳入当前 token 或图片体积预算：`嵌入块内容：内容超预算不展开`，保留原始嵌入 SQL，不区分具体超出的预算类型；
  - 丢失/无权限/隐私过滤：按「查无此块」处理，不显示真实来源路径或 ID，不泄露目标是否存在。
- 统计口径：「嵌入内容共X个块，当前展示N个块」中的块 = 嵌入内容解析出的展示块数（嵌套嵌入块计 1 块，停止层计 0）；统计行与提示行每个嵌入块末尾都必须存在（含 0 结果、丢失、无权限、隐私过滤及预算停止）。隐藏目标不计入结果数、展示数、token 或图片体积统计。
- 嵌入内容按完整块处理，不截断；SQL 匹配条数上限 20（暂定，常量），超出部分不渲染，差距由统计行体现。超过上限的可见匹配计入总数 X（每条按一个块计），当前展示数 N 只计实际渲染块；隐藏匹配不计入 X 或 N。
- 嵌入块始终占 1 个展示块，前后序号不受嵌入内容影响；大纲不含嵌入内容标题。

## 技术方案

- 改动点：`build_display_blocks()`（source_code/mcp_server.py）新增 `resolve_embeds` 参数，默认 False；仅 `siyuan_read` 路径开启，其余调用点行为不变。
- 渲染流程：从 `{{}}` 提取 SQL → `client.query_sql` 执行 → 先做可见性与隐私过滤 → 渲染可见匹配块并拼入该展示块 Markdown。
  - 文档型目标：对目标文档递归走同一套展示块渲染。
  - 标题型目标：按思源默认语义渲染「标题 + 下方内容至同级/更高级标题」。
  - 其他块型：直接用块 Markdown 渲染。
  - 嵌入图片及附件链接按各自来源文档解析、提取到对应来源文档的附件目录，不按宿主文档解析。
- 嵌套与循环：嵌入内容内再遇嵌入块按同一逻辑递归，带深度上限和已访问集合（对齐内核 resolveEmbedR 思路）。
- 安全与隐私：
  - 仅接受 SELECT 语句，其余保留原文不渲染；
  - 每个 SQL 匹配在读取目标内容、渲染及计算 token/图片体积预算前，先过 Privacy Rules 与可见性过滤（复用搜索路径过滤逻辑）；
  - 不可见目标视为查无此块，不渲染、不计入命中和统计，也不输出其路径、ID 或过滤数量；
  - 匹配数上限 20（暂定），统计仅基于可见结果。
- 预算与窗口语义：
  - 一个嵌入块是原子展示块：只有完整嵌入内容能纳入当前剩余 `token_budget` 和本次 read 的图片体积预算时才展开；嵌入内容不切半。图片预算沿用当前 read 的单笔响应预算，与宿主文档及其他嵌入共用，不按来源文档重置；图片内联的开关和计价沿用当前 `siyuan_read` 规则。
  - 保持现有连续窗口算法，不跳过超预算块探测后续块。已有块占用预算后，若下一个嵌入块的完整展开超预算，当前窗口停在它之前，下一窗口从该嵌入块开始。
  - 下一次从超大嵌入块开始读取时，如果完整展开仍超预算或渲染无法安全完成，则降级为该块原始 SQL，并输出 `嵌入块内容：内容超预算不展开`；本次正文只返回该嵌入块，不再试探后续宿主块，下一窗口从其后的展示块开始。
  - 预算检查和异常处理必须保证大型嵌入不会导致 MCP 调用失败；对非首块的预算停止和首块的 SQL 降级保持上述窗口语义。
  - 若嵌入块完整展开后仍有预算但后续宿主块超预算，后续块留给正常的下一窗口处理。

## 思源侧机制实测（2026-09-29，思源 3.8.5）

测试文档：/测试思源桥专用/嵌入块效果（含普通嵌入、嵌套嵌入、循环嵌入 A/B 三个用例）。

- 前端 UI：嵌入内容带文档路径面包屑逐层渲染；直接打开的文档内自嵌显示「不存在符合条件的内容块」（前端查询 excludeIDs 含 rootID）；从父文档进入时循环链展开数层后渲染为空壳。
- 内核 export（`exportMdContent`，start 同源）：
  - 正常嵌套全部递归展开、内联，无任何来源标注（AI 经 start 无法区分宿主内容与嵌入内容）；
  - 循环由 `resolveEmbedR` 深度上限 7 打断（kernel/model/render.go:315-318），实测最多展开 7 层，超深嵌入块以原始 `{{...}}` 文本留在导出中；
  - `resolved` 列表记录嵌入块节点 ID（render.go:340-343），但插入内容经 `parse.Parse` 重建、节点 ID 重新生成（render.go:470），export 中实际起打断作用的是深度上限；
  - 嵌入 SQL 命中嵌入块本体时跳过不渲染（render.go:355-357）；结果条数受 Conf.Search.Limit 上限（render.go:348）；带访问过滤（render.go:353）；
  - `embedMode: 1` 时内核原生把嵌入内容逐行包 `"> "` 引文（render.go:456-467），与本方案 read 的引用格式同源。

## 桥 read 的循环与防护设计

- 递归防护：同一嵌入块 ID 在一条渲染链上只展开一次（A 嵌 B、B 又嵌 A 时，第二个 A 的嵌入处即停止），另设深度上限 7 兜底（对齐内核）。
