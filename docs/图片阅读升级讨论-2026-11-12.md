# 图片阅读升级

状态：已获用户授权实施。现行契约见 ARCHITECTURE.md「阅读模型」，完成后更新该处并清理本讨论稿。

## 已确认的目标

- 保留现有 read 入口、图片开关与 include_large_images 参数，升级对人与 AI 几乎无感，不新增日常步骤。
- 标准版利用主流模型正常读图能力，在文字与数字可读的前提下尽量减少传输体积；优先容量，不以编码速度决定方案。
- 大图版保留原像素且不做有损压缩；原始附件始终不修改。
- 长宽比严格超过 3:1 时沿长边按短边切成近方形；全部切片按顺序一次返回，作为一张原图的完整组处理，体积及视觉 token 为组内各片之和。不得只发送部分切片。
- 整条 MCP 返回（含 Base64、文字和 JSON）遵守 10 MB 硬上限，不能再用大图参数绕过消息限制。
- 图片依赖自动获取，保存在思源桥自有目录并复用，支持多个下载来源；缺失或失败时通过思源提示，不要求用户运行安装命令。

## 实施范围

1. 独立本地图片处理模块：方向纠正、长图裁剪、标准版编码与尺寸控制、大图版无损裁剪、按尺寸估算视觉 token。
2. 独立依赖准备模块：按实际 Python/系统匹配固定版本二进制 wheel，固定 SHA-256 校验，多来源下载及私有目录解包；不调用系统 pip、不修改全局环境。插件加载时检查准备情况，首次运行自动完成准备。
3. 接入现有图片内联流程，宿主、嵌入、引用和列表共用；处理完成后才按整组计算预算。
4. 文本分页与图片估算分开：文本预算控制分页，返回中仍报告包含实际图片估算的合计，避免固定每张 1568 token 阻止已经压小的图片返回；所有图组保持完整。
5. 对最终多模态响应做序列化大小复核，缩窗只移除完整展示块；无法容纳的首块图片明确说明，不静默部分返回。
6. 同步 schema、Skill、中英文 README、架构、前端与验证指南。

标准版初始候选为长边 2576、不放大、WebP 有损 quality=90/method=6，并比较无损与原编码；最终以真实样本验证确定。裁剪边界保留少量重叠以保护被切断的字行，记录每片原始坐标。

## 验证

- 单元测试覆盖阈值、横竖图、尾片、像素覆盖、无损还原、完整组预算、最终消息字节数、网络图、依赖来源失败切换及私有路径。
- 开发版 MCP 真实读取产品介绍营销（860×14040，17 片）、培训长海报（1440×8265，6 片）、课程截图、研究图表与照片；普通及引用阅读均检查顺序与返回大小。
- 亲自查看实际发送的图片，核对文字、数字和图表细线；大型改动按开发指南执行独立验收。
- 测试产物留在原仓库 image-processing-probe/20261112，私人图片不得加入 Git 或发布包。只提交本次源码及文档，不推送、不部署用户版，开发版保持可用。
