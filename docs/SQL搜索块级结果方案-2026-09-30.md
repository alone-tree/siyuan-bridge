## 用户已明确的结果规则

## 原始需求案例

《谷歌每日快讯》文档 `20251215171116-bhf5rll` 内的 SQL：

```sql
SELECT * FROM blocks
WHERE root_id = '20260106101341-tm2v3t5'
  AND content LIKE '%2026年%'
  AND (content LIKE '%#谷歌#%' OR content LIKE '%#Google#%')
ORDER BY created DESC
```

实际调用现有 `siyuan_find(mode="sql")` 只返回一条《每日新闻汇总》文档记录，没有命中块内容。本需求要求保留逐块命中，而非折叠为文档清单。

## 官方接口补充实测（2026-09-30，思源 3.8.5）

通过已登录思源页面用 Playwright 直接调用官方接口，仅查询以上测试文档或用递归 CTE 生成数字，不读取隐藏文档。

### 原始 SQL 接口 `/api/query/sql`

- `mode=readonly` 调用成功；响应顶层除了 `code/msg/data`，还实际包含 `limit` 与 `truncated`。
- 数字序列测试：生成 63 条 → 返回 63 条，`limit=64, truncated=false`；生成 64 条 → 返回 64 条，`truncated=false`；生成 65 条 → 返回 64 条，`truncated=true`。
- 生成 1000 条、不带 LIMIT → 返回 1-64，`limit=64, truncated=true`，无完整总数。
- 同一数字查询加 `LIMIT 30` → 返回 1-30；加 `LIMIT 30 OFFSET 30` → 返回 31-60。两者 `limit=0, truncated=false`，表明主动 SQL LIMIT 不作为自动截断标记。
- `SELECT id FROM blocks ...` → 实际返回 4 条 ID，沿用 SQL 顺序。

### 官方全文搜索 SQL 模式 `/api/search/fullTextSearchBlock`

- `method=2, groupBy=0`，以上测试 SQL 的 `SELECT *` 实际返回 4 个完整块，顺序 A1 → B1 → A2 → B2；含 `matchedBlockCount=4, pageCount=1`。
- 相同查询只 SELECT id → 返回空块数组（code=0），与原始 SQL 接口不同。前端嵌入查询同样不能直接消费只 SELECT id 的结果。
- `pageSize=2`，page=1 返回 A1/B1，page=2 返回 A2/B2；两次均 `matchedBlockCount=4, pageCount=2`。
- SQL 带 `LIMIT 2 OFFSET 2`，page=1 → 返回 A1/B1 而非 A2/B2：此入口改写 SQL OFFSET，不能当作原始 SQL 分页入口。
- 命中文档块时只返回标题，`markdown` 为空，不会替桥完成用户要求的前 20 个正文块展开。

### 已采用的技术方案

- 保留 `/api/query/sql` 作为召回入口：已有调用链、尊重 SQL LIMIT/OFFSET，官方直接提供自动截断标记，不需要维护 SQL 解析器。
- 只从用户 SQL 行提取 `id`，分批查询真实 `blocks` 元数据（仅身份与路径列、显式 LIMIT，避免身份查询被默认 64 条截断）；由真实来源校验可见索引、隐私规则和系统文档硬过滤后才读取正文。伪造 root_id、路径、content 不影响输出；不存在或无 id 的行不作为命中，不输出任意列报表。SQL 重复行保留。
- 文档渲染复用 `build_display_blocks()`，不启用嵌入解析或引用阅读；正文块用 `getBlockKramdown` 获取完整文本。图片改为普通链接，保留原地址，不提取附件。
- 可见性过滤不等于数据库级隔离；任意 SQL 可通过隐藏数据谓词影响可见命中。本次范围不包含 SQL 重写或数据库隔离。
- 保留接口顶层 `limit/truncated`。现有 `client.query_sql()` 仅取 data，会丢掉这些信息；修改时应保持其他内部调用兼容。
- 自动截断时，只提示「上游查询已截断，仍有候选未返回；可在原查询中使用 LIMIT/OFFSET 继续查询」，不宣称剩余候选可见，也不透露隐藏数量或编造总数。
- 示例：当前无显式 LIMIT 的响应已取前 64 个候选，继续可用 `LIMIT 64 OFFSET 64`（保留排序；OFFSET 按原始候选数推进，不按过滤后可见数推进）。
- 用户显式 LIMIT 的范围由用户 SQL 自身决定；`truncated=false` 不表示 LIMIT 之外不存在数据。
